# tapestry-ai-sdlc-poc

AI 辅助软件交付（SDLC）的验证仓库。这里放的是"让 agent 参与需求 → 实现 → 评审 → 合并"这条流水线的最小闭环，不是业务系统本身。

## 账号分工

| 角色 | GitHub 账号 | 负责 |
| --- | --- | --- |
| 执行 | `allenxu-lego` | 领取任务、写代码、推 `agent/*` 分支、开 PR、在 PR 上留评审意见 |

| 合并 | 人 | PR 由人合并，agent 不合并、不替他人批准 |

提交作者署名是 `dsh-superagent`（挂在 `allenxu-lego` 账号的 noreply 邮箱下），这样 git 历史里能区分出哪些改动来自 agent。

## 怎么派活

在飞书群里 @ 机器人，一句话说明目标、范围和验收标准。请求内容里请给出：

- 涉及哪些文件或目录；
- 改完怎么算对（可执行的检查、测试或明确的对照标准）；
- 不在本次范围内的事，避免顺手扩大改动面。

需要设计决策的，agent 会停下来提一个具体问题，而不是替你猜。

## 约定

- 不要把密钥、token、内部地址提交进来；本地凭据一律放 `.local-secrets/`（已被忽略）。
- 目录结构、技术栈与分支策略尚未定型，第一个真实任务会把这些写进 `AGENTS.md`。
